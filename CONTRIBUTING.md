# Control de cambios

1. Registra un problema o mejora con la plantilla de issue.
2. Crea una rama descriptiva, por ejemplo `docs/manual` o `fix/unidades-altura`.
3. Implementa un cambio acotado y actualiza documentación y CHANGELOG.
4. Ejecuta la validación apropiada y adjunta evidencia anonimizada.
5. Abre un pull request con problema, cambio, verificación y limitaciones.

No incluyas API keys, modelos Revit ni resultados reales sin autorización. Mantén los datos generados fuera del repositorio. No cambies una convención BIM sin registrar el criterio acordado.

Usa etiquetas de versión solo para entregas verificadas. Esta base no asigna una versión de producto retrospectiva.
